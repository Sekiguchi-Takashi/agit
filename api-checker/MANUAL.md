# API連携チェッカー 利用マニュアル

スマホのブラウザだけで、Gemini APIキーがHTML/JavaScriptから正常に呼び出せるかを確認するためのツールです。
同じ仕組みで、今後使いたい **Google Maps API / Gmail API / LINE Messaging API** もテストできるようになっています。

対象ファイル: `index.html`（このファイルと同じフォルダにあります）

---

## 1. できること

- Gemini APIキーを入力して「テスト実行」を押すだけで、実際にAPIを呼び出し、応答が返ってくるかを確認できます。
- 結果（OK/NG、応答内容の一部）を画面に表示し、履歴として残します。
- 履歴を「チェックファイル」として端末に保存できます（テキストファイル `check_日時.txt`）。
- サービス選択を切り替えるだけで、Google Maps / Gmail / LINE Messaging API も同じ画面からテストできます（ただし認証方式がそれぞれ異なるので、3章を参照してください）。

このツールは **サーバーを使わない単一のHTMLファイル** です。入力したキーはこの端末から各サービス（Google / LINE）に直接送られるだけで、どこにも保存・送信されません。

---

## 2. 事前準備：Gemini APIキーの取得

1. スマホのブラウザで [Google AI Studio](https://aistudio.google.com/apikey) を開く
2. Googleアカウントでログイン
3. 「APIキーを作成」を押し、表示されたキー（`AIza...` で始まる文字列）をコピーしておく

---

## 3. ファイルをスマホで開く方法

### 方法A：ファイルをスマホに置いて直接開く

1. `index.html` をスマホの内部ストレージ（例: `Download` フォルダなど）にコピーする
   - PCから転送する、またはスマホのブラウザでこのファイルをダウンロードする
2. スマホの「ファイル」アプリ（Android標準の「Files by Google」など）で `index.html` を探す
3. ファイルをタップし、「Chromeで開く」などブラウザで開くことを選択する

### 方法B：GitHub Pagesなどで公開して開く（任意）

リポジトリをGitHub Pagesで公開している場合は、そのURL（例: `https://<ユーザー名>.github.io/agit/api-checker/`）をスマホのブラウザで直接開いても構いません。

---

## 4. 使い方（Geminiの場合）

1. ページを開くと、サービス選択は初期状態で **「Gemini API」** になっています
2. 「APIキー」欄に、2章で取得したキーを貼り付ける
   - 入力欄の右の「表示」ボタンで、貼り付けた内容を確認できます
3. 「テスト実行」をタップする
4. 数秒待つと結果が表示されます
   - **OK（緑色）**: Gemini APIキーが正常にHTMLから呼び出せています。「詳細を見る」でAPIからの応答テキストを確認できます
   - **NG（赤色）**: キーが無効、権限不足、通信エラーなどです。表示されたエラー内容を確認してください（7章のトラブルシューティングも参照）

---

## 5. チェックファイルの保存方法（内部ストレージ／Documentsフォルダ）

テストを1回以上実行した後、画面下部の **「チェックファイルを保存」** ボタンをタップすると、`check_YYYYMMDD_HHMMSS.txt` という名前のテキストファイルがダウンロードされます。

ブラウザの仕様上、JavaScriptから保存先フォルダを直接指定することはできません。**「内部ストレージ／Documents」フォルダに保存したい場合は、以下の設定をしておくと保存時にフォルダを選べます。**

### Android + Chromeの場合

1. Chromeを開き、右上の「⋮」→「設定」→「ダウンロード」を開く
2. 「ダウンロード前に保存先を確認する」を **ON** にする
3. この状態で「チェックファイルを保存」をタップすると、保存先を選ぶダイアログが表示される
4. ダイアログで `内部ストレージ` → `Documents` フォルダを選択し（フォルダが無ければ「フォルダを作成」で `Documents` を作成）、「保存」をタップする

設定をONにしていない場合は、既定の `Download` フォルダに保存されます。その場合は、スマホの「ファイル」アプリで `Download` フォルダ内のファイルを `Documents` フォルダに移動（コピー）してください。

## 6. 今後使いたいAPIのテスト方法

サービス選択を切り替えると、入力欄のラベルやヒントが自動的に変わります。それぞれ認証方法が異なるので注意してください。

### Google Maps API（Geocoding APIで動作確認）

- 入力するもの: **APIキー**（Gemini同様、文字列1つ）
- 取得先: Google Cloud Console → 「APIとサービス」→ 認証情報 → APIキーを作成し、「Geocoding API」を有効化する
- 「確認用の住所」欄（既定値: 東京駅）を変更すると、別の地名で検索テストができます
- 備考: Google Cloud Console側でHTTPリファラー制限をかけている場合、別ドメインからのテストは失敗することがあります。テスト時は制限を一時的に外すか、テスト用の制限なしキーを使ってください

### Gmail API（OAuth2が必要・APIキーでは動作しません）

- 入力するもの: **OAuth2アクセストークン**（`ya29....` のような文字列）。Gmail APIはAPIキー単体ではユーザーデータにアクセスできません
- アクセストークンの簡単な取得方法（動作確認用）:
  1. [Google OAuth 2.0 Playground](https://developers.google.com/oauthplayground) を開く
  2. 右側の「Select & authorize APIs」で `Gmail API v1` → `https://www.googleapis.com/auth/gmail.readonly` を選択し「Authorize APIs」
  3. 自分のGoogleアカウントでログイン・許可する
  4. 「Exchange authorization code for tokens」を押すと **Access token** が発行されるので、それをコピーしてチェッカーに貼り付ける
  - 注意: この方法はその場の動作確認用です。本番でアプリに組み込む場合は、別途OAuthクライアントを自分のGoogle Cloudプロジェクトで作成し、正式な認可フローを実装してください
- アクセストークンには有効期限があります（通常1時間程度）。期限切れの場合は再発行してください

### LINE Messaging API

- 入力するもの: **チャネルアクセストークン**
- 取得先: [LINE Developersコンソール](https://developers.line.biz/console/) → 対象チャネル → 「Messaging API設定」→「チャネルアクセストークン（長期）」を発行
- 備考: LINEのAPIはブラウザからの直接呼び出し（CORS）を許可していない場合があります。「通信エラーが発生しました（CORS等の制限の可能性があります）」と表示された場合は、トークン自体が無効というより、ブラウザの仕様上の制限によるものです。本番でLINE連携する場合は、サーバー側（バックエンド）経由で呼び出す構成にしてください

## 7. トラブルシューティング

| 症状 | 主な原因 | 対処 |
|---|---|---|
| HTTP 400 / 403 | APIキーが無効、該当APIが有効化されていない、権限不足 | キーを再発行する／Google Cloud ConsoleでそのAPIを有効化する |
| HTTP 401 | トークンが無効・期限切れ（Gmail / LINE） | トークンを再発行する |
| 通信エラー・CORSの可能性 | ブラウザの仕様上、外部APIへの直接アクセスが拒否されている | サーバー経由での呼び出しに切り替える（本ツールはあくまで簡易確認用） |
| 何も起きない・ボタンが反応しない | 入力欄が空、通信圏外 | キーを入力し直す／通信状況を確認する |

## 8. 今後さらにAPIを追加したい場合

`index.html` 内の `SERVICES` というJavaScriptオブジェクトに、サービスごとの設定（表示名・入力欄のラベル・テスト関数）を1つ追加するだけで、選択肢に新しいAPIを増やせる構成になっています。新しいAPIを追加したくなったら、既存のGemini/Maps/Gmail/LINEの定義を参考に同じ形で追加してください。

---

## 9. セキュリティ上の注意

- APIキー・トークンは第三者に渡さないでください。チェックファイルにはキーの一部のみ（先頭4文字・末尾4文字）を記録するようにしていますが、それでも他人に共有しないことを推奨します
- このキー・トークンをGitなどのリポジトリにコミットしないでください
- キーが漏れた・漏れた可能性がある場合は、発行元の管理画面（Google Cloud Console / LINE Developersコンソール）で速やかに無効化・再発行してください
